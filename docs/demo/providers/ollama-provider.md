# Ollama Provider

> **ab\* skill**: `ab-provider-config` | **Status**: ✅ implemented

## What it is

The Demo includes **Ollama** as a fallback LLM provider, configured via
`UseOllama(model, endpoint, apiKey)` in `Program.cs`. This allows running the
Demo with a local/self-hosted LLM when no OpenAI key is available.

## Why this matters

Not every team has an API key, and not every environment can reach the internet. Ollama
lets you run a fully local LLM on your own machine — no API key, no network latency, no
cost per token. It is the fast path for evaluating AgentBlazor in a sandbox: install
Ollama, pull a model, and the Demo works out of the box. In production, it is also the
path for air-gapped or privacy-sensitive deployments where data cannot leave your
network.

## Where to find it in the Demo

- `Program.cs` → `UseOllama(model, endpoint, apiKey)` as fallback after OpenAI
- Requires a running Ollama instance (default: `http://localhost:11434`)

## How to experience it

1. Install and start [Ollama](https://ollama.ai) locally.
2. Pull a model: `ollama pull llama3.2` (or any compatible model).
3. Do **not** set an OpenAI API key (or clear it).
4. Start the Demo — it falls back to Ollama.
5. Navigate to any workflow and send a prompt.
6. The agent uses the local Ollama model to generate responses.

## What to observe

- Responses are generated by the local model (quality may vary).
- No API key is required.
- Response latency depends on local hardware.
- If neither OpenAI nor Ollama is available, the app throws a security error.
