# OpenAI Provider

> **ab\* skill**: `ab-provider-config` | **Status**: ✅ implemented

## What it is

The Demo uses **OpenAI** as its primary LLM provider, configured via
`UseOpenAI(apiKey, model)` in `Program.cs`. The default model is `gpt-4o-mini`.
A `DemoSecurity` guard ensures a provider is configured before the app starts in
production.

## Why this matters

Every AgentBlazor agent needs an LLM provider to function — it is the brain behind
the agent. OpenAI (GPT-4o-mini) is the default because it offers a good balance of
cost, speed, and quality for most use cases. The provider configuration is where you
choose which model powers your agents and how it is authenticated. In production, you
would typically use a provider key from Azure OpenAI or a similar managed service.

## Where to find it in the Demo

- `Program.cs` → `UseOpenAI(apiKey, model)` with fallback to `gpt-4o-mini`
- `Configuration/DemoSecurityOptions.cs` → `RequireProviderInProduction` guard
- API key provided via `OpenAI:ApiKey` in user secrets or environment variables

## How to experience it

1. Set your OpenAI API key:
   ```bash
   dotnet user-secrets set "OpenAI:ApiKey" "sk-..."
   dotnet user-secrets set "OpenAI:Model" "gpt-4o-mini"
   ```
2. Start the Demo.
3. Navigate to any workflow and send a prompt.
4. The agent uses the OpenAI model to generate responses.

## What to observe

- Responses are generated by the configured OpenAI model.
- The model name appears in agent metadata/logs.
- If no API key is set, the app falls back to Ollama (if available) or throws
  a security error in production.
