# AgentBlazor 0.2.25-internal.4

> **Private/internal fork build.** This version is published only to the private local feed (`AGENTBLAZOR_LOCAL_FEED`, default `%USERPROFILE%\.agentblazor-feed`) and is **not** intended for public consumption.

## Breaking: `AgentDefinitionEntity` aligned 1:1 with the runtime model

The persistence base entity now mirrors `AgentRegistration` (the runtime/hydrated
model) column-for-column:

- **Added `AllowedCapabilityActionsJson`** — JSON array of capability action IDs
  (`["capabilityId.localActionId"]`), mirroring `AgentRegistration.AllowedCapabilityActions`.
  Previously capability actions were persisted into `AllowedActionsJson` (a lossy
  conflation); the Demo seeder now writes them to their own column.
- **Removed `Persona` and `EnabledToolsJson` columns** — the custom persona and
  enabled-tool whitelist are now carried in `MetadataJson` under the
  `agent_builder.persona` / `agent_builder.enabled_tools` keys, mirroring
  `AgentRegistration.Metadata` 1:1. `MetadataJson` is the single source of truth
  and round-trips with `Metadata` without re-attachment logic.

**Migration for consumers on `0.2.25-internal.3`:** drop `Persona` /
`EnabledToolsJson` and move their values into `MetadataJson` under the
`agent_builder.persona` / `agent_builder.enabled_tools` keys (see the Demo's
`20260916010547_DropPersonaAndEnabledToolsJson` migration for reference).

## Demo: single-write agent builder

- **`DatabaseBackedAgentRegistry`** — `ApplyRegistration`/`ToRegistration` now
  round-trip `MetadataJson` ↔ `Metadata` 1:1 (no persona/enabled-tools
  re-attachment). `SetCustomization` is reframed as a convenience for a
  **customization-only** update path (e.g. a persona editor that does not touch
  the definition); the builder's save path does not need it.
- **`AgentBuilder.razor`** — `SaveAsync` builds the full `AgentRegistration`
  (persona + enabled tools in `Metadata`) and calls `AddOrUpdate` **once**;
  the redundant `SetCustomization` call is gone.
- **`DemoDbContext`** — maps `AllowedCapabilityActionsJson`; drops `Persona` /
  `EnabledToolsJson` mappings. Two new migrations:
  `20260916005112_AddAllowedCapabilityActionsJson`,
  `20260916010547_DropPersonaAndEnabledToolsJson`.
- **`Program.cs`** — seeding persists `AllowedCapabilityActions` to its own
  column (workflow agents keep their capability actions).

## New consumer skill: `ab-agent-builder` (20th ab-* skill)

End-to-end runtime agent authoring for consumer apps: users author, edit, and
delete custom agents on demand, persisted to SQL Server via EF Core, served
through a consumer-owned store-backed `IAgentRegistry` (the replace path)
composed with the `IAgentRuntimeCustomizer` seam. Includes:

- `AgentDefinitionEntity`-derived store + SQL Server `DbContext` guidance
- Store-backed `IAgentRegistry` as the authoring surface (`GetAll` /
  `AddOrUpdate` / `RemoveAgent` — no separate service layer)
- Tool catalog for the picker (`IAgentServiceToolRegistry` +
  `IAgentCapabilityRegistry`) and per-agent tool **restriction** semantics
  (whitelist `EnabledToolIds` enforced by `ChatClientRuntimeAdapter`)
- Full copy-paste page code-behind scaffold (tool picker, single-write save,
  edit, delete) grounded in the Demo's `AgentBuilder.razor`

**Updated skills:** `ab-agent-registration`, `ab-context-assembly`,
`ab-entity-design`, `ab-multitenancy`, `ab-skill-selector` (catalog, chain
playbooks, evals) — reconciled with the aligned entity model and the new skill.
Plugin metadata: `plugin.json` → 0.2.27, marketplace → 0.2.26, `AGENTS.md`
skill list updated.
