# AgentBlazor 0.2.23-internal.1

> **Private/internal fork build.** This version is published only to the private local feed (`AGENTBLAZOR_LOCAL_FEED`, default `%USERPROFILE%\.agentblazor-feed`) and is **not** intended for public consumption. The `-internal.1` suffix is an unmistakable private marker so a future public `0.2.23` cannot collide after merging upstream `master`.

`0.2.23` adds a durable library-level fix for the GPT-5.6-family `reasoning_effort` rejection bug and documents the provider ChatOptions seam.

## Highlights

- Added `AgentBlazorRegistrationOptions.ConfigureChatOptions(Action<ChatOptions>)` — a provider-level hook to configure the `Microsoft.Extensions.AI.ChatOptions` applied to every agent turn.
- Fixes: gpt-5.6-luna / gpt-5.6-sol / gpt-5.6-terra reject function tools on `/v1/chat/completions` with HTTP 400 naming `reasoning_effort` when the server-side default reasoning effort is non-none — even if the client never sends the parameter.
- The hook is applied **clone-first**: AgentBlazor wraps the registered `IChatClient` in a `ConfigureOptionsChatClient` (MEAI `AsBuilder().ConfigureOptions(...)`), so the callback mutates a per-request clone and never the caller's own `ChatOptions` instance. The consumer's pre-existing `ChatOptions` are preserved (temperature, max tokens, tools, tool mode, etc.).
- Empirically validated with an in-repo HTTP wire-capture harness (`HttpListenerWireServer`) that records the exact request bodies sent to the provider:

| Path | Wire result |
| --- | --- |
| `ConfigureChatOptions(ReasoningEffort.None)` + OpenAI provider | `"reasoning_effort":"none"` on the wire, tools + `tool_choice` intact |
| Streaming turn | `reasoning_effort` pinned on the streaming request |
| Workflow agent (tool loops) | pin present on **both** tool requests |
| Azure OpenAI provider | pin **is** emitted (AzureOpenAIClient derives from OpenAIClient; same chat-completions adapter) |
| Ollama provider | pin emitted (`"reasoning_effort":"none"` — inert for Ollama) |
| No hook registered | client left unwrapped; wire body identical to 0.2.22 |

## Migration

If you previously applied the consumer-side workaround (manually wrapping the registered client after `AddAgentBlazor`), replace it with the library hook:

```csharp
using Microsoft.Extensions.AI;

builder.Services.AddAgentBlazor(options =>
{
    options.UseOpenAI(apiKey: config["OpenAI:ApiKey"]!, model: config["OpenAI:Model"]!);

    // GPT-5.6-family models reject function tools with HTTP 400 (reasoning_effort)
    // unless reasoning effort is explicitly pinned to none.
    options.ConfigureChatOptions(o => o.Reasoning = new ReasoningOptions
    {
        Effort = ReasoningEffort.None
    });

    options.ConfigureBuilder(agentBuilder => { /* ... */ });
});
```

## Safety Notes

- The pin flows into every agent turn through the provider-level `IChatClient` singleton — including the paid `LlmAdaptiveSuggestionService` / `LlmProactiveInsightService` / `SqliteSmartSuggestionService` paths and any direct `IChatClient` resolvers. This is benign (explicitly pinned effort, same model family), but be aware the scope is provider-wide, not per-agent.
- Per-provider semantics: OpenAI maps `ReasoningOptions` → `reasoning_effort`; Azure OpenAI emits it too (same adapter); Ollama accepts it as inert; the custom OriginAI SSE client ignores `ChatOptions` entirely.
- `ReasoningOptions` / `ReasoningEffort` in MEAI carry `[Experimental(AIOpenAIReasoning)]` — the experimental attribute is on the MEAI types, not on `ConfigureChatOptions` itself.
- Multi-tenant: the hook applies when the singleton `IChatClient` registered by `UseOpenAI()` / `UseAzureOpenAI()` / `UseOllama()` is present. If you replace the client with a per-tenant proxy (multitenant blueprint), pin effort per-tenant inside your factory instead — see `docs/multi-tenant-production-blueprint.md`.
- `ConfigureChatOptions` is not a replacement for the Responses API (`api.responses.write`). If a model family requires Responses-API semantics, escape via the provider's native client; the provider options seam stays chat-completions.
