# AgentBlazor 0.2.27-internal.1

> **Private/internal fork build.** This version is published only to the private local feed (`AGENTBLAZOR_LOCAL_FEED`, default `%USERPROFILE%\.agentblazor-feed`) and is **not** intended for public consumption.

## New: `AgentRuntimeCustomization.UserContext` — user-scoped runtime context

The runtime customization seam (`IAgentRuntimeCustomizer` / `AgentRuntimeCustomization`) is
re-framed to two concerns: the **tool-whitelist restriction** (`EnabledToolIds`) and
**user-scoped business context** (`UserContext`).

- **`UserContext`** (`IReadOnlyDictionary<string, string?>`) is a new 3rd positional
  parameter on `AgentRuntimeCustomization`. It is injected into the turn's user message
  "Runtime context:" block in **both streaming and non-streaming** paths.
- **Merge semantics:** channel-supplied `AgentTurnRequest.Context` keys win on collision;
  `null`/empty values are skipped (honest degradation — Never-Fabricate).
- **The agent persona is NOT part of the seam.** It is *user-managed instructions*: authored
  in the Agent Builder flow and merged into `AgentRegistration.Instructions` at store-backed
  registry hydration (`platform\n\npersona`), so it is maintained during authoring, never
  constructed at chat runtime.
- **`Instructions` is deprecated** (`[Obsolete]`, still functional) for one internal version
  as a migration path for consumers using the seam for genuine per-turn instruction
  injection. The old model broke the LLM's cached system-prompt prefix on every change;
  `UserContext` lives in the user-message tail, so per-user volatile data never invalidates
  the cached system+schema+tools prefix (see the KV-cache/token-cost section in
  `ab-context-assembly`).

### New: `AgentRuntimeCustomizationKeys`

`AgentBlazor.Core.Runtime.Customization.AgentRuntimeCustomizationKeys` standardizes the
`agent_builder.persona` / `agent_builder.enabled_tools` metadata keys that store-backed
registries use to persist the customization — consumers reference the constants instead of
hardcoding the strings.

## New: `AgentChatSurface.UserId` parameter

`AgentChatSurface` accepts an optional `UserId` (string?) — the host-owned identity threaded
into every `AgentTurnRequest` (send, clarification, approval continuation) and into
suggestion refresh. It feeds `GetEffectiveUserId()`, which the customizer uses to scope
per-user business context. Unset behavior is byte-identical to before.

## New: Demo user-scoped runtime context showcase

- **`DemoUserContextProvider`** (identity / activity / domain layers) — identity from
  `DemoUserDirectory`, activity from real persisted session counts (cache-aside 30s
  `IMemoryCache`), domain from **live mutable business state** via the async
  `IProvideLiveUserContext.GetLiveUserContextAsync` contract on 4 workflow services.
- **Agent Builder page** splits **platform-managed instructions** (read-only, seeded at
  startup) from the **user-managed persona** (editable textarea) and adds a "Chat as user"
  picker wired to `AgentChatSurface.UserId`.
- **`DatabaseBackedAgentRegistry`** merges the persona into `AgentRegistration.Instructions`
  at hydration (non-destructive — the metadata key is preserved), caches the hydrated
  registration so edits are visible next turn, and exposes `TryGetRuntimeCustomization`
  (tools only).

## Renamed: `Runtime`-suffixed customization methods

The naming pass emphasizes "agent customization at runtime per turn":

| Before | After |
|---|---|
| `IAgentRuntimeCustomizer.GetCustomizationAsync` | `GetRuntimeCustomizationAsync` |
| `ChatClientRuntimeAdapter.ResolveCustomizationAsync` (private) | `ResolveAgentRuntimeCustomizationAsync` |
| `DatabaseBackedAgentRegistry.TryGetCustomization` | `TryGetRuntimeCustomization` |
| `DatabaseBackedAgentRegistry.SetCustomization` | `SetRuntimeCustomization` |

## Upgrade notes

- **One source-breaking rename:** `IAgentRuntimeCustomizer.GetCustomizationAsync` →
  `GetRuntimeCustomizationAsync`. The seam is young (internal builds only, Low divergence
  per `DIVERGENCE.md`); the rename is mechanical. `AgentRuntimeCustomization.Instructions`
  remains functional (obsolete) — no removal.
- **No other breaking changes.** `AgentChatSurface.UserId` and
  `AgentRuntimeCustomization.UserContext` are additive; `AgentRuntimeCustomizationKeys` is a
  new file.
- **Version bump target:** this release is `0.2.27-internal.1`; the previous was
  `0.2.26-internal.2`.
