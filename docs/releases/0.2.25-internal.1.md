# AgentBlazor 0.2.25-internal.1

> **Private/internal fork build.** This version is published only to the private local feed (`AGENTBLAZOR_LOCAL_FEED`, default `%USERPROFILE%\.agentblazor-feed`) and is **not** intended for public consumption.

## New: Runtime customization seam (consumer P1)

Adds a per-agent, per-turn customization hook inside the runtime adapter — the supported path for per-agent system-instruction injection and tool selection (the consumer's Tier-2-style customization requirement; see `.agent-handoffs/260909-tier2-runtime-adapter-feasibility.md`).

- **`IAgentRuntimeCustomizer`** — `Task<AgentRuntimeCustomization?> GetCustomizationAsync(AgentRegistration, AgentTurnRequest, CancellationToken)`.
- **`AgentRuntimeCustomization(Instructions?, EnabledToolIds?)`** — custom instructions (appended after registration instructions, before the READ-SAFE data-schema block) and a logical-id tool whitelist.
- **`AgentBlazorBuilder.AddRuntimeCustomizer<T>()` / factory overload** — single customizer, last registration wins (mirrors `UseRuntimeAdapter`).
- **Integration** (`ChatClientRuntimeAdapter`): resolved **exactly once per turn** from the run-execution scope; threaded through the early-exit tool check and agent creation; skipped for session-state creation (`request == null`).
- **Tool filtering by logical id** pre-projection: capability → full `ActionId` (`{capabilityId}.{localActionId}`), component → `ComponentId.ActionId`, service/MCP → raw name. Generated-UI tools and legacy component aliases are **reserved** (always projected). `null`/empty whitelist = no filtering.
- **No-op when unregistered** — standard agents incur zero additional work (locked by a counting-customizer test).

## Additive only — no breaking changes

`AgentTurnRequest`, `AgentRegistration`, `IAgentRuntimeAdapter`, and `IConversationStore` are untouched.
