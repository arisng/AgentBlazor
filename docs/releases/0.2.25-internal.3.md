# AgentBlazor 0.2.25-internal.3

> **Private/internal fork build.** This version is published only to the private local feed (`AGENTBLAZOR_LOCAL_FEED`, default `%USERPROFILE%\.agentblazor-feed`) and is **not** intended for public consumption.

## New: First-class persistence base entities in AgentBlazor.Core

Abstract base entity classes for consumer app persistence are now shipped in the
`AgentBlazor.Core` NuGet package under `AgentBlazor.Core.Persistence`. Consumer apps
inherit from these and optionally extend with multitenancy, soft-delete, audit columns,
etc. — the consumer owns the `DbContext` and EF Core configuration.

### Base entities

- **`ConversationSessionEntity`** — `int Id`, `string SessionId` (unique index),
  `string? UserId`, `DateTime CreatedAtUtc`, `DateTime LastActivityAtUtc`,
  `List<ConversationTurnEntity> Turns`.
- **`ConversationTurnEntity`** — `int Id`, FK `SessionId`, `string TurnId` (unique per
  session), user/agent messages, action plan/result JSON, timestamps, and **7 token cost
  columns**: `PromptTokens`, `CompletionTokens`, `TotalTokens`, `CachedInputTokens`,
  `EstimatedCost`, rate snapshots for historical audit.
- **`AgentDefinitionEntity`** — `Guid Id`, `string Name` (unique), `string? Instructions`,
  JSON collections for allowed components/actions/data-schemas/tools, persona, metadata.

### Design principles

- **Database-agnostic** — no SQLite, SQL Server, or PostgreSQL-specific code in the
  library. Consumer apps provide their own EF Core `DbContext` and provider configuration.
- **TPC (table-per-concrete-type)** — abstract roots use `UseTpcMappingStrategy()`.
  Consumer apps must handle integer identity generation for their chosen provider.
  SQLite+TPC consumers should use client-side value generators (see Demo project for
  reference implementation).
- **Extensible** — consumer apps add their own properties (e.g., `TenantId`,
  `IsDeleted`, `CreatedAt`/`UpdatedAt` audit) by overriding or extending the base entities.

### Demo project refactoring

- **Unified `DemoDbContext`** replaces the split `DemoConversationDbContext` +
  `DemoAgentDbContext`. All 3 entity hierarchies (sessions, turns, agent definitions)
  mapped via TPC with SQLite-specific identity workarounds.
- **`DemoDatabaseOptions`** config section (`appsettings.json` → `DemoDatabase:ConnectionString`)
  replaces hardcoded connection strings. Design-time factory (`DemoDbContextFactory`) reads
  from the same config for `dotnet ef` tooling.
- **Code-first migrations** — `MigrateAsync()` at startup replaces the legacy
  `DemoConversationDatabaseInitializer` additive column pattern. Initial migration
  scaffolds all 3 tables.
- **Deleted**: `DemoConversationDbContext`, `DemoAgentDbContext`, `DemoAgentDatabaseSeeder`,
  `DemoConversationDatabaseInitializer`, separate `.db` files.

## Upgrade notes

- Consumers pinning to `0.2.25-internal.2` can update with no breaking changes to
  `AgentBlazor.Core` APIs.
- The new `AgentBlazor.Core.Persistence` namespace provides optional base entities —
  adopting them is entirely at the consumer's discretion.
- Demo-only changes (unified DbContext, config conventions, migrations) do not affect
  library consumers.
